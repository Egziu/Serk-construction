## Open risks a human approver must weigh (High and above, and notable Medium)

- **R-SIGNER custody (High).** The signing key is now isolated in `serk-signer`, out of the API process. The signer and the database both check every claim against the person's token, project scope and session revocation. But whoever controls the signer process or its secret controls approvals. An HSM/KMS keyring and a human key ceremony are needed.
- **R-MFA-SOURCE (High).** MFA assurance is only as good as the IdP integration, which is not connected (GATEA-02 and GATEA-07 BLOCKED).
- **GATEA-12 (High for production).** `go.sum` hashes have never been compared with sum.golang.org, and `govulncheck` has never run. Both are unreachable from this environment.
- **Unreviewed fixes (Medium).** The corrections for reviews 10–12 (migrations 0035–0037) have been verified by the delivering agent only.
- **R-DBA (Medium).** The database owner or superuser can still disable controls. The owner is now non-superuser-capable (0034) and the posture check refuses a superuser owner in production. Off-host evidence and pgaudit alerts are not set up.
- **R11-F5 (Low/Medium).** Someone with delete rights on the offsite store can remove the newest backup objects undetected. Object-lock storage and monitoring are needed.
- **R-BANKFEED (Medium).** Settlement relies on statement files imported by an independent officer. Their authenticity depends on how the file is obtained, because there is no bank-signed feed.

## Safety constraints in force

- No production deployment, no production credentials, no payment commands and no access to live tenant data. All tests ran against disposable local databases with synthetic data.
- No AI principal holds payment, approval or posting authority. The database accepts authority only from attestations signed by the isolated signer for an authenticated human session; it re-checks the person's project scope and session revocation from signed markers (0035/0036). Since 0014/0015, payment approval and release also require the platform-signed `principal.human` marker, which comes from the identity provider's principal-kind assertion; no role can grant it.
- Payment instructions are records only. Nothing in this system moves money; settlement is recognised only from imported bank statements.
